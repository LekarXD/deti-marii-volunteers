# «Опора» — платформа волонтёров фонда «Дети Марии»

Хакатон, кейс 3. Одно место, где фонд ведёт волонтёра от анкеты до участия и мотивации, а координатор управляет базой волонтёров и мероприятиями.

- **Стенд:** https://www.odschool.ru/deti-marii/ — на нём работает текущий `main`, версия видна в `/version.json`.
- **Telegram-бот:** [@detimarie_bot](https://t.me/detimarie_bot), подключается из профиля на сайте.
- **Стек:** React + TypeScript (`apps/web`), FastAPI + PostgreSQL 16 (`apps/api`), бот на aiogram (`bot/`), Docker Compose (`infra/`).

**Волонтёр**
1. «Стать волонтёром» → анкета на 3 экрана → кабинет «Анкета проверяется» (`/application`).
2. В кабинете — запись на встречу с координатором и «Познакомиться с фондом»: 4 модуля и тест из 10 вопросов (`/onboarding`).
3. После встречи открывается лента мероприятий `/events`: «Подобрано для тебя», запись, резерв. До встречи запись закрыта.
4. Мои занятия `/my/schedule`, часы, уровни и баллы `/hours`.
5. Профиль → «Подключить Telegram»: приглашения с кнопками «Приду / Не смогу» и напоминания приходят в бот.

**Координатор**
1. `/fund/candidates`, `/fund/interviews` — анкеты, встречи, итог встречи.
2. `/fund/events/:id` → «Пригласить на роль» — кого позвать, с причиной.
3. `/fund/volunteers` — база и статусы. `/fund/signals` — кого пора позвать или поддержать.
4. `/fund/notifications` — рассылки. `/fund/prizes` — призы за баллы.
5. `/fund/reports` — отчёты. `/fund/integrations/dobro/transfers` — перенос часов в Добро.рф.

## Как мы закрываем запрос фонда

Проблема из кейса: «Нам сложно в одном месте сопровождать волонтера на всем пути: от подачи заявки и обучения до подбора задач, участия и мотивации».

| Блок кейса | Что сделано | Где |
|---|---|---|
| Профиль волонтёра | контакты, навыки и интересы, когда свободен; опыт, формат и регулярность — из анкеты | `/profile`, `/application` |
| Знакомство и обучение | знакомство с фондом из 4 модулей и тест; академия: статьи, записи, тренажёр; координатор отмечает обязательные материалы | `/onboarding`, `/academy`, `/fund/learning` |
| Каталог возможностей | лента мероприятий с записью и резервом, направления фонда с откликом | `/events`, `/opportunities` |
| Подбор | формула по трём признакам: роль, знакомая группа, время; координатору — подсказки, кого позвать | `apps/api/app/modules/activities/ranking.py` |
| Учёт участия | история занятий, часы после отметки координатора, справка о часах в PDF | `/my/schedule`, `/hours` |
| Коммуникация | уведомления на сайте, переписка с координатором, рассылки, Telegram-бот | `/messages`, `/fund/notifications`, `bot/` |
| Мотивация | уровни по часам (20, 50, 100), 10 баллов за час и ×1,5 за мероприятия, где не хватает людей, +100 за знакомство с фондом, призы, вехи | `/hours`, `/fund/prizes` |
| Рабочее пространство фонда | база волонтёров, статусы, журнал контактов, сигналы, приглашения, согласование, отметка участия | `/fund/*` |

## Решения

- **Подбор без машинного обучения.** Формула `0.4·роль + 0.4·знакомая группа + 0.2·время`. На синтетической истории обученные веса не дали прироста (AUC 0,707 против 0,705), а языковая модель ранжировала хуже формулы (0,768 против 0,781 на той же выборке). Расчёт — `materials/05-продукт/Мэтчинг волонтёров и мероприятий.md`, скрипты — `scripts/`.
- **ИИ не обязателен.** Всё работает без него. Любой OpenAI-совместимый провайдер подключается переменными `OPORA_AI_*`, по умолчанию ИИ выключен. Личные данные провайдеру не передаются (`apps/api/app/modules/knowledge/README.md`).
- **Telegram — второй канал.** Бот работает через API сайта от имени человека, своей базы мероприятий не ведёт (`bot/README.md`).
- **Добро.рф.** Публичного API нет, поэтому сделан ручной перенос часов с правилом «не больше 8 часов в сутки» (`apps/api/app/modules/dobro`).

## Тесты

- 211 тестов API (`apps/api/tests`), 473 теста интерфейса (`apps/web/src`).
- Проверки бота — `bot/tests`, сквозные проверки — `tests/e2e`.
- Проверки целиком — `infra/scripts/verify.sh`.
- GitHub Actions в этом приватном репозитории не стартуют: GitHub отклоняет задачи из-за лимита оплаты аккаунта. Это видно в аннотации любого запуска; проверки запускаются командой выше.

## Запуск локально

Нужны Docker Compose, Node 22+, pnpm 11.3, Python 3.12.

```sh
cp infra/.env.example infra/.env
# замените пароль в infra/.env
docker compose --env-file infra/.env -f infra/compose.yaml up --build -d
curl --fail http://127.0.0.1:8001/ready
```

Сайт откроется на http://127.0.0.1:8080. База при этом пустая. Тестовые аккаунты создаёт `python -m app.cli fixtures g1 --json` в `apps/api`, код входа из локального почтового ящика показывает `python -m app.cli dev-inbox --email <почта>`. Подробно — `infra/README.md`, раздел без Docker — там же.

## Что не сделано

- Приглашения на закрытые мероприятия фонда.
- Импорт волонтёров из таблиц.
- Уведомление о переносе времени занятия.
- В карточке волонтёра у координатора нет его участия и часов; фильтры базы — по статусу и имени.
- Excel только из бота, на сайте его нет.
