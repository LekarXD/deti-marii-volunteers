# Вход и регистрация: локальная демонстрация

Ветка `codex/welcome-login`. Этот контур работает отдельно от серверной сборки и её базы.

## Сценарий

- Неавторизованного посетителя встречает страница с двумя действиями: «Войти» и «Стать волонтёром».
- Вход: почта и пароль, ссылка на восстановление, возможность показать пароль. Все формы расположены в одной центральной карточке: заголовок, поля, основное действие. Дублирующая подпись бренда и отдельная колонка с вводным текстом убраны.
- Регистрация: почта и пароль → код → анкета. До подтверждения сервер запрещает запись анкеты. Почта в анкете берётся из сессии и не редактируется.
- После подтверждения показывается меню аккаунта, а не кнопка входа. Переход на главную направляет в подходящий кабинет или незаполненную анкету.
- В шапках используется официальный логотип фонда; приветствие использует картину с сайта фонда. Источники перечислены рядом с ассетами.

## Почта пока не подключена

`OPORA_DEMO_EMAIL_CODES=true` разрешает любой непустой код для регистрационных запросов, созданных в демонстрационном режиме. Письма для таких запросов не ставятся в очередь. Интерфейс прямо сообщает, что подойдёт любой код.

Флаг допускается только в development/staging; production с этим флагом не запускается. Восстановление через произвольный код доступно только аккаунтам, созданным в демонстрационном режиме. Обычные аккаунты и второй фактор координатора этот режим не обходят.

Для подключения настоящей почты нужно выключить флаг и настроить существующую доставку: интерфейс переключится на шестизначный код из письма.

## Четыре аккаунта

Один координатор и три волонтёра, только вымышленные контакты `example.test`. Анкеты и история участия пока не заполнены. Пароли и резервные коды находятся в локальном файле `.local/accounts.md` с правами 0600; в Git их нет.

`python -m app.prototype_demo seed --credentials-path <private-path>` создаёт аккаунты только в development с включённым demo-флагом и только в базе `opora_welcome_demo`. Повторный запуск проверяет маркер и исходный приватный файл, не меняя пароли. Команда `code` с тем же путём выдаёт текущий TOTP тестового координатора.

Локальные сервисы: frontend 5175, API 8002, PostgreSQL 56158. Для браузера используется `http://welcome.localhost:5175/`: отдельное имя хоста исключает пересечение с cookies других локальных сборок. `OPORA_DEV_API_ORIGIN` позволяет направить Vite на отдельный API; по умолчанию остаётся 8001.

- Все 313 фронтенд-тестов прошли; TypeScript и production-сборка прошли. Девять HTTP-тестов парольного входа и восстановления прошли на отдельной PostgreSQL.
- В браузере пройдены регистрация с произвольным кириллическим кодом, открытие анкеты, выход, парольный вход волонтёра, парольный вход и TOTP координатора.
- Проверено: после подтверждения нет кнопки «Войти», почта анкеты read-only, координатор открывает обзор фонда.
- Приветствие и формы проверены на ширине 320 и 390 px, горизонтального переполнения нет.
- Восстановление пароля проверяется HTTP-тестами; в браузере проверен переход к форме восстановления без смены паролей подготовленных аккаунтов.
- Проверены повторный запуск генератора аккаунтов и отсутствие их секретов в Git.
