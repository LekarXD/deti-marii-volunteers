# P18B live studio

`WebinarsPage({staff?:boolean})` exports the real schedule, draft/publish and enrollment UI. `LiveRoomPage` reads the `sessionId` route parameter; links use `/studio/:sessionId`, `/fund/webinars` and `/webinars`. Root mounts these modules with lazy route imports under existing Opora top navigation. No root/sidebar/layout duplication and no camera/microphone request on render.

`useLiveKit(sessionId, scene)` is the ordinary resource-neutral host/audience hook. It creates no provider room or device track until explicit action. `controller.connect(scene)` asks the current server for a grant. Camera/microphone/screen buttons prompt only after a host click; provider room presence must be acknowledged by `/ready` before the UI reports a live session. Reconnect obtains a fresh API grant. Device selection/provider failures stay visible and never report success locally.

The private renderer imports `live/HiddenCaptureController.ts` directly; this import does not pull in the ordinary cookie API, board editor, chat or product pages. It requires approved CapturePlan privacy and exact resource/take/generation/revision/profile/policy bindings before constructing a provider room. Unsafe plan updates clear bindings and unsubscribe immediately. Reconnect blocks pending fresh private bootstrap. The SDK-mandated short-lived room JWT is the only provider URL credential; purpose tickets remain header-only and no credentials are persisted.

`board/BoardConnection.ts` ports pinned OD `boardConnection.js` mechanics at `38c92cd49b1b6c229ed473de991479ed261e4052`: same Y.Doc across grant refresh, manual scoped WebSocket transport, no BroadcastChannel, bounded renewals, local namespaces. Each fresh grant is validated by the actual sidecar/API. Delayed refresh/unmount is fenced; a changed room cannot receive the old document. Libraries load lazily using exact pinned packages; fonts/locale assets are served from `/studio-board-assets/`, never a public CDN. Root's copy step supplies that directory from the installed package.

`BoardCanvas` ports Yjs/Excalidraw binding, view fitting and local-origin undo. Editor controls sit outside StudioStage. `boardStageBinding` mounts a view-only live board into the canonical Stage content rectangle; every scene/surface revision fences readiness. Dynamic-board capture is deliberately blocked by shared Stage until a signed read-only board projection/clock/manifest contract exists. An approved immutable PNG snapshot is stored through scoped API/assets; it is not claimed as a continuous board recording.

Scene composition comes exclusively from `packages/studio-core` and `ui/studio/StudioStage`. Slides bind immutable server page metadata, and preview verifies fetched bytes against the scene checksum before creating a temporary object URL. Object URLs and tracks are cleaned up. Uploads resume from authoritative server offsets; dead conversion jobs expose failure/retry state instead of spinning forever.

Verification: focused controller/board/UI tests, full TypeScript check and a dedicated feature-entry Vite build (including actual LiveKit/Excalidraw dynamic chunks). Server tests cover actual PostgreSQL concurrency/ACL, fenced slide jobs and real PDF conversion. Actual loopback LiveKit signaling smoke proves issued-token reconnect after self-hosted removal; this does not prove WebRTC media, physical devices, two-browser A/V, continuous board capture or final video composition. Those remain explicit integration acceptance steps.
