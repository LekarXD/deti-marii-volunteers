# Messages UI

Exports `MessagesPage` (also CandidateMessagesPage / CoordinatorMessagesPage). Mount inside the shared AppProviders + candidate/coordinator layout. Routes should be `/messages` and `/fund/messages`; A0 owns route wiring.

All DTOs import generated `components` and all requests use shared `api`; no private fetch client or QueryClient. Root regenerates the SDK after mounting the backend router. The local generated schema used for compilation is not part of this feature commit.

Design reference: canvas «Сообщения — новый экран чата» (https://claude.ai/artifact/D7zCVfZvNGrfPry726DKwd). The chat fills the window under the header (`--messaging-offset` in `messages.css` is the space above and below; a page that adds anything above the chat must raise it). One card: 360px dialogue list with search, last message, time and unread count; conversation on the right with grouped bubbles (one time per group, names and avatars only in group chats), a sticky day label and a one-line composer (paperclip, growing field, round send button; Enter sends on desktop, Shift+Enter is a new line). On phones the list and the conversation are separate screens and the app header hides inside a conversation. Read-only system channel, loading/error/empty states and persisted messages stay. AI summary is not shown until it exists. Raw images still require a no-people confirmation before send; PDFs go out without one. PDFs and PNG/JPEG/WebP up to 10MB use the common acknowledged upload lifecycle.

Focused UI tests cover draft isolation between threads, Enter/Shift+Enter, image policy gating and retrying an unknown send outcome with the same key. Backend HTTP tests separately establish two actual authenticated sessions, ACL revoke, unread, attachment links, and receipts; mocked UI tests alone do not prove browser/backend integration. Visual/mobile and two-context browser integration are the A0/A8 acceptance gate.
