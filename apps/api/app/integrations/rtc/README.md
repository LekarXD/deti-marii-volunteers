# P18B provider seam — first implementation checkpoint

Source pin: `curator-bot` commit `38c92cd49b1b6c229ed473de991479ed261e4052`, specifically `livekit_auth.py`, `livekit_rooms.py`, `livekit_join.py`, `sidecar_tokens.py` and the browser media/board adapters. This namespace ports JWT grant and bounded Twirp mechanics. It replaces school course IDs, issuer subjects, storage prefixes and implicit role checks with Opora UUIDs and fresh resource authorization.

`RtcSettings` uses `OPORA_RTC_URL`, `OPORA_RTC_PUBLIC_URL`, `OPORA_RTC_API_KEY`, `OPORA_RTC_API_SECRET`, `OPORA_RTC_DEPLOYMENT=self_hosted|cloud`, and optional separate `OPORA_RTC_BOARD_URL`/`OPORA_RTC_BOARD_SECRET`. No provider configuration means `rtc_unavailable`; no token is issued. Secrets stay server side. Browser tokens never grant `roomAdmin`, `roomRecord`, room creation, arbitrary data publishing or audience media publishing.

The adapter exposes capabilities explicitly. Strict revocation policy fails closed on self-hosted deployments **before token issuance**. For Cloud, removal includes an explicit `revoke_token_ts`; provider acknowledgement is still required by the operational service. Self-hosted removal does not invalidate existing tokens, and provider-refreshed tokens can last longer than the initial short TTL. A successful HTTP token denial is insufficient proof of an already-issued token's invalidation. See the primary [LiveKit token lifecycle documentation](https://docs.livekit.io/frontends/reference/tokens-grants/).

P18B owns one resource-neutral operational StudioSession/room/scene lifecycle. P18C capture sessions/takes/renders reference that session UUID, rather than creating a second room source. Scene and capture-plan JSON must validate against P18A `packages/studio-core/*.schema.json`; scene geometry and rendering remain solely in P18A. A1 recording-project resource authorization is supplied as an explicit callback. Host and audience media grants require current foundation/resource membership/enrollment, not an email suffix or frontend role choice.

The next checkpoint adds purpose-bound immutable slide deck conversion through P01 assets/jobs and the full pinned Yjs/Excalidraw board sidecar in an Opora namespace. Shared worker registry and upload factories belong to A1. Heavy conversion runs only in the dedicated media workload. RTC/board bundles are lazy route imports; they do not load in the candidate questionnaire.

Tests at `modules/studio/tests/test_rtc_adapter.py` use real HS256 tokens and a controlled HTTP transport to verify grants, webhook exact-body hashes, explicit Cloud cutoff, self-hosted capability denial and an already-issued token remaining valid after self-hosted removal. They do not constitute real provider/two-browser/media proof. No staging or production provider has been contacted at this checkpoint.
