## Формат `.dc.html` (нарушение = артборд молча не рисуется)
```html
<!doctype html>
<html lang="ru">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Название экрана — Опора</title>
<script src="./support.js"></script>
</head>
<body>
<x-dc>
…helmet из kit/helmet.html…
<div class="dm"><div class="shell"> …шапка роли… …контент… </div></div>
</x-dc>
<script type="text/x-dc" data-dc-script data-props='{"$preview":{"width":1440,"height":1800}}'>
class Component extends DCLogic {
  constructor(props){ super(props); this.state = { tab: 'all' }; }
  renderVals() { return { isAll: this.state.tab === 'all', setAll: () => this.setState({ tab: 'all' }) }; }
}
</script>
</body>
</html>
```
- Строку `<script src="./support.js"></script>` сохранить ДОСЛОВНО. Закрывать все не-void элементы, атрибуты в кавычках.
- `{{hole}}` — только точечный lookup в `renderVals()` (`{{item.title}}`), НИКАКИХ выражений (`{{a+b}}`, `{{!x}}`). Всё
  вычисляй в `renderVals()`. Логика — classic JS, `class Component extends DCLogic`, без import/export, без `render()`.
- Ветвления: `<sc-if value="{{isX}}" hint-placeholder-val="{{true}}">…</sc-if>`. Списки:
  `<sc-for list="{{items}}" as="it" hint-placeholder-count="3">…{{it.title}}…</sc-for>`. Обработчики: `onClick="{{pick}}"`,
  для элемента списка — функция внутри элемента: `items.map(x => ({...x, pick: () => this.setState({sel: x.id})}))`.
- Вся разметка — в `<x-dc>`, никаких innerHTML/appendChild/window.X. Без `<iframe>`, без глобальных keydown, без сети
  (кроме Google Fonts из helmet). НЕ используй `<table>` вообще (`<sc-for>` внутри table ломается) — таблицы делай сеткой
  `.tbl` / `.tbl-row` с `grid-template-columns` в inline style.
- Ссылки между артбордами: `<a href="Catalog.dc.html">`. Кнопку-ссылку стилизуй на самом `<a class="btn …">`, не кладя
  `<button>` внутрь `<a>`.
- Атрибут `data-props` — в одинарных кавычках, JSON. В нём только `$preview` (ширина 1440, высота — твоя оценка высоты
  страницы). Без лишних «tweaks».
- Корень флюидный: `.dm` + `.shell` (max-width 1280). На ширине телефона всё складывается (grid-2/3/4 уже auto-fit,
  `.split` переносится). Ширины в px только у мелочей.
- Интерактив: состояние в `state`, переключение вкладок, выбор элемента списка, шаги мастера, раскрытие карточки —
  через `setState` + `<sc-if>`. Каждый артборд должен ЖИТЬ: минимум 2–3 рабочих взаимодействия.
- Состояния экрана для показа (пусто, ошибка, другой вариант) — переключателем `.demo` в самом верху контента под шапкой
  (как в эталоне): `<div class="demo" role="group" aria-label="Состояния для показа"><span class="demo-cap">Показать:</span><button …>`.
  Не плоди артборды на каждое состояние.

## Правила дизайна (владелец строго, проверяй себя)
Стиль: светлый тёплый фон фонда, Inter, графитовый текст, брендовый оранжевый для главного действия, жёлтый — выбранное/
активное (как на сайте фонда), синий — ссылки и инфо, зелёный — готово, красный — тревога, фиолетовый — ИИ.
Компоненты — из дизайн-кода дизайнера «Общего Дела»: плавающая навигация-пилюля, кнопки-пилюли, тонированные статусы,
поля с подписью сверху, карточки радиусом 24 без теней, мягкий градиент только у героя (`.card-hero`).
- ОДНО главное действие на экран (одна `btn-primary` в зоне видимости). Остальные — secondary/ghost/subtle.
- Текст ≥15px. 13px (`.meta`) — только мета (даты, размеры). Без мелких поясняющих подписей под каждым элементом:
  пояснение только у того, что сломано или требует действия. Спокойное — без подписей.
- Без карточек в карточках. Список внутри карточки — строками `.li` с линейками, не вложенными карточками.
- Статус — `.tag` (тонированная пилюля) ИЛИ `.dot` (точка + слово). Не вешай пилюлю на каждую строку: один тон тревоги.
- Никаких эмодзи, Cinzel, градиентов «для красоты», левых цветных полосок, теней (кроме навигации — уже в ките),
  капса, жирности 800+. «·» как разделитель не использовать — ставь отдельные элементы с gap.
- 2–3 визуальных якоря на экран: герой (`.card-hero`), сгруппированные списки в карточках (одна карточка на группу),
  ведущий визуал в строке (аватар с инициалами, `.art` с иконкой мастерской, превью видео с длительностью), полоса прогресса.
- KPI-цифры — `.kpi` с цветной кляксой `.blob` за числом (мотив сайта фонда: цифры на цветных пятнах).
- ИИ помечай `.ai-tag` (иконка sparkle + «ИИ») и ИИ-панели — `.ai-box`. Всегда показывай, ЧТО предлагает ИИ и что
  РЕШАЕТ человек (кнопки «Принять / Исправить / Отклонить»), и почему (объяснение, источники, цитаты).
- Реальные элементы: `<button type="button">`, `<a href>`, `<input>`+`<label for>`; у иконки-кнопки `aria-label`.
  Недоступное — `aria-disabled="true"` + причина словами рядом, не бледность.
- Необратимое (отклонить заявку, удалить материал) — с подтверждением (второй шаг в state).
- Фото детей НЕ используем (приватность). Иллюстрации — `.art` с иконкой и тоном мастерской.
- Копирайт: коротко, по-человечески, на «ты» с волонтёром, на «вы» в письмах/отчётах. Без канцелярита, без пафоса,
  без метафор («Один шаг к добру» — нельзя; «Записаться» — можно). Без «ИИ» в каждой фразе.

## ИИ в продукте (где и как показывать)
1. Профиль из «о себе» (заявка/профиль): свободный текст → навыки, интересы, опыт с детьми, доступность — чипы «ИИ нашёл»,
   волонтёр подтверждает/правит.
2. Подбор с объяснением (каталог, главная) + «кого позвать» и срочная замена (смены координатора).
3. Тренажёр трудных ситуаций (академия) + разбор по критериям с цитатами.
4. ИИ-наставник «что делать, если…» — RAG по базе знаний фонда, ответ с источниками; нет ответа → «передать координатору».
5. База знаний для инструктора: загрузка документов, индексация, «вопросы без ответа» (пробелы), проверка ответа.
6. Рефлексия после занятия → настроение, трудности, просьбы, тревожные сигналы о ребёнке → координатору/психологу.
7. Разбор заявки: выжимка, совпадение с ролями, что проверить, вопросы к собеседованию. Без автоотказов.
8. ИИ-соавтор урока из методички; конспект+тест из записи вебинара.
